# Toner

[English](README.md) | [中文](README_zh.md) | [设计思路 / Design Rationale](DESIGN_zh.md)

Toner 是一套面向 AI Agent（如 Antigravity、Claude Code、Cursor 等）的文本语气与表达规范，用于清除大语言模型在回答、文档起草和学术写作中常见的模板化套话、伪学术词汇与过度叠甲，建立直接、严密、高信息密度的输出标准。

---

## 为什么需要 Toner？

大语言模型在生成中文与技术文本时，普遍存在以下表达弊病：
- **习惯性叠甲与免责**：频繁添加“需要注意……”“存在风险……”“因人而异……”等套话。
- **机械反转对仗**：高频滥用“不是……而是……”“并非……而是……”来制造虚假的逻辑深度。
- **生造数量复合词**：随意拼凑“双重机制”“四视角分析”“二步骤流程”等非标准缩写，强行营造学术感。
- **跨学科借用硬科技术语**：在日常描述或社科文境中生搬硬套“解耦”“正交”“鲁棒”“闭环”“熵增”等工程词汇充当修辞。
- **文科黑话与评论腔**：堆砌“迷思”“祛魅”“图景”“底色”“赋能”“抓手”等抽象大词，稀释事实密度。

Toner 通过明确的红线规则与自检机制，消除上述表达习惯，让 AI 回归平实、准确、结论先行的交流本位。

---

## 核心规则规范

### 1. 沟通原则与信息密度
- **直接回答**：第一句直接给出结论、方案或目标代码，严禁客套寒暄、身份说明或空洞背景铺垫。
- **拒绝过度叠甲**：依据充分时果断下结论；仅在存在真实技术不确定性时说明边界。
- **信息密度优先**：删除无增量信息的过渡句、总结句与三段式同义词堆砌。

### 2. 编辑与润色保真
- **忠实于原文事实**：严禁增加未提供的数值、日期、人名、引文或因果推断；绝不把“相关”改成“因果”，绝不把“可能”改成“确定”。
- **尊重通顺文本**：仅修改存在明显语法或逻辑缺陷的语句，通顺部分予以保留，不为体现修改量而强行重写。
- **保护格式要素**：保持代码块、行内代码、URL、Markdown 锚点与 YAML 头部完整。
- **直接交付成稿**：润色后直接交付最终文本，不输出修改草稿或评分过程。

### 3. 句式与用词红线
- **禁用反转对仗句式**：一律禁用“不是……而是……”及“并非……而是……”，直接正面陈述事实证据与核心逻辑。
- **禁用生造数量复合词**：除公认专业术语（如“双重差分法 DID”“多任务学习”）外，严禁生造“双任务范式”“二步骤”“三维度”“四视角”等缩写。遇到多项任务或流程，拆解为自然平实的完整表述。
- **禁用跨学科术语借用**：严格限制物理、数学、计算机专有名词的适用场景，在非对应学科中改用平实词汇（如“解耦”改为“分离/分别测量”，“正交”改为“相互独立”，“鲁棒”改为“稳健/可靠”）。
- **禁用文学化与评论腔词汇**：禁用“迷思”“祛魅”“图景”“底色”“异化”“规训”等词汇，禁用“赋能”“抓手”“闭环”“链路”等企业黑话。

### 4. 双模式切换
- **Mode A（直接答复模式）**：适用于日常问答、代码排错、技术讨论。结论先行，允许使用紧凑列表与精简对比表格。
- **Mode B（正式文档与论文模式）**：适用于学术论文、立项申请与技术报告。以严密的连续段落叙述为主，避免用碎片化清单代替论证；正文引文严格按顺序递增编号（`[1]`, `[2]`, `[3]`）。

## 安装与配置

### 1. 作为 Agent Skill 使用（Antigravity / Claude Code）
直接克隆或复制本仓库到本地 Skill 目录：

```bash
git clone https://github.com/SLEEX/Toner.git ~/.agents/skills/toner
```

或者仅复制 [SKILL.md](SKILL.md)：

```bash
mkdir -p ~/.agents/skills/toner
cp SKILL.md ~/.agents/skills/toner/SKILL.md
```

### 2. 作为全局或项目提示词规则使用
在任何支持系统指令的编程或写作环境中（如 Cursor、OpenCode、Codex 或任意 LLM API），将 [SKILL.md](SKILL.md) 中的规则直接追加至项目规则文件中：
- `CLAUDE.md`
- `AGENTS.md`
- `.cursorrules`
